## PlayMode

`GameFlowTests` 验证：

- 主场景初始化到开始页；点击开始、选择可用关卡后进入选武器阶段。
- 选择手枪后开始门打开。
- 进入游戏和到达出口会产生正确阶段变化。
- 能连续切换到第十关并生成安全灯。
- 第十关对象池按 14 个敌人的上限完成预热。
- 开始游戏后，敌人会经过出生预警再进入活动状态。
- 统一输入层能够驱动 CharacterController，并切换第一/第三人称视角。
- 第七关以后，玩家离开安全灯范围会受到瘴气伤害。
- 装备后能实际穿过入口进入迷宫。
- 砍刀挥击能伤害前方无遮挡的敌人。
- 手枪准心对准敌人时可命中并消耗一发弹药。
- 已装备但尚未进门时可以暂停、恢复到准备阶段，并返回选武器。
- 小地图不会提前暴露终点；走到相邻格后探索数增加，重新开始则恢复到起点。

## Windows Player 烟测

正式包支持命令行 `-fogboundSmoke`，单独使用会停在开始页。
加 `-fogboundLevels` 查看选关；加 `-fogboundLoadout` 查看武器页；加 `-fogboundGameplay`
才会选武器并进入游戏。`-fogboundFirstPerson -fogboundWalkRoute` 检查第一人称实体路线。
`-fogboundScreenshot` 后接截图绝对路径。烟测使用独立进度键，不会修改正常玩家的通关记录。
日志必须包含 `FOGBOUND_RUNTIME_SMOKE_PASS`，路线测试还需 `FOGBOUND_WALK_PASS`，并检查 C# 异常。

历史 `v1.0.1` 曾对选武器、第三人称、第一人称手枪和第一人称砍刀运行真实
Windows Development Player 可见窗口烟测，四组均有截图和 PASS 日志。
这些名称和流程只用于说明早期版本，不代表当前玩法。当前 `v1.4.0` 已改为默认长刀、
栓动狙击枪随时切换，并完成 Windows 与 Android Release 构建；作者已在 Android 真机
验证怪物追击、死亡结算、第一人称侧墙检测和武器比例。最后一轮仅调整终点与出生灯光，
自动测试和构建通过，但作者决定不再重复进行该 APK 的真机观感复测。

## 人工测试边界

自动化可以验证规则和流程，但不能替代手感判断。后续回归或新版本发布前应人工检查：

- WASD、鼠标、冲刺、攻击、换弹和视角切换。
- 栓动狙击枪和长刀各完成至少一次有效战斗，确认拉栓、手动换弹、开镜和近战反馈。
- 局部雾区、固定地下城环境状态、深渊蛮兵、污染区和避难灯能够被玩家理解。
- Windows 与 Android 真机输入没有遮挡或失控；WebGL 若重新发布，需要单独完成浏览器交互回归。
- 终点绿色灯与怪物出生红灯不会明显穿墙暴露位置。
- 第十关出口进入 Boss 大厅，击败深渊狱长后牢笼开启，靠近公主才结算胜利并解锁 Boss Replay。

文档不会把尚未执行的人工测试写成 PASS。
