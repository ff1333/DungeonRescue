# 落地道具碰撞与迷宫通路修复

日期：2026-11-16
状态：Windows Development 候选已构建，尚未发布

## 试玩反馈

大块碎石等装饰遮住画面，玩家与怪物能走进模型。v1.5.1 的 `MazeWorld.CreateProp()` 为避免堵路，统一禁用了道具的 Collider；这使装饰没有实体边界。

## 实现与取舍

- 只给碎石、木桶、木箱、桌子和宝箱等落地道具添加根节点 `BoxCollider`；火炬、旗帜、钥匙等壁挂装饰保持纯视觉。Boss 大厅石柱保留已有的独立掩体碰撞。
- 随机落地道具按关卡 seed 放在格子角落，水平占地最多 1.4m；入口、出口与 Boss 房的落地道具最多 1.8m。依据模型渲染边界调整尺寸和底部位置，再根据原网格局部边界生成碰撞盒，避免静态合批影响子物体碰撞。
- 不改变逻辑迷宫、A*、玩家和怪物 CharacterController。碰撞变化可能影响实际走位和攻击遮挡，因此用实体通路及 PlayMode 回归验证，而不只看网格是否连通。

## 验证

- 直接添加碰撞后的首轮十关通路测试失败：第 2 关开放通道被大模型堵住；加入占地限制后该测试通过。
- EditMode `32/32`；PlayMode 第二轮 `58/58`。首轮完整 PlayMode `57/58`，长刀命中测试单项重跑通过，第二轮完整通过；该项需继续关注时序稳定性。
- Windows Development 构建成功，`0 errors / 0 warnings`：`Builds/Windows/Development/DungeonRescue.exe`。
- 独立 Player 隐藏窗口自动走位截图运行 120 秒仍无通过标记或图片，已结束进程，不计为视觉验证。仍需作者人工复核大块装饰附近的第一/第三人称视野、玩家和怪物贴边移动。`v1.5.1` GitHub Release 与 Android APK 尚未包含本修复。

## 面试讲法

逻辑网格可达不代表三维场景实体可走。装饰物首次加入时为了不阻挡路线被设置为无碰撞，试玩后暴露了穿模；直接开启碰撞又堵住开放通道。我把道具尺寸、摆放和简化碰撞一起控制，并在十关实体通路测试中回归。
