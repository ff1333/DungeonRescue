# v1.5.1 奇幻美术统一开发记录

日期：2026-11-14

## 问题

v1.5.0 的玩法和 Boss 流程完整，但玩家与公主共用同一角色，Boss 与精英怪共用同一模型；墙地面以基础几何体为主，剧情身份和地下城空间层次不足。

## 资源决策

使用 KayKit Adventurers、KayKit Skeletons 和 KayKit Dungeon Remastered。三个仓库均为 CC0，源地址、原许可证、下载缓存和集成边界记录在 `Assets/Art/KayKitFantasy/SOURCE.md` 与 `THIRD_PARTY_NOTICES.md`。

本轮没有把第三方模型描述为原创建模。项目工作集中在资源选型、导入设置、动画映射、骨骼挂点、材质、运行时装配和回归验证。

## 实现

- 玩家改为兜帽冒险者，公主改为独立法师角色。
- 普通怪改为骷髅仆从并携带短刃，精英怪改为重甲骷髅并携带战斧/盾牌。
- Boss 改为独立骷髅法师，携带法杖，保留弱点核心并增加阶段材质色变化。
- `FogboundFantasyArtBuilder` 统一选择 Legacy 动画片段、重命名为项目接口、分配 URP 材质、附加装备并生成 Resources 预制体。
- 玩家武器挂点兼容 KayKit 的 `handslot.r`、`hand.r`、`chest` 骨骼，保留双手姿态、背负武器和贴墙收枪。
- 迷宫按固定 seed 增加火炬、蜡烛、木箱、木桶、碎石、旗帜、宝箱、钥匙和石柱。装饰禁用碰撞，不参与 A* 或攻击遮挡。
- Boss 大厅保留原掩体碰撞，关闭基础柱体 Renderer 后叠加装饰石柱，避免视觉升级改变战斗尺寸。

## 首轮回归暴露的问题

1. `MaterialPropertyBlock` 在 MonoBehaviour 字段初始化器创建，PlayMode 报 Unity 生命周期异常。改为在 Boss 初始化时创建。
2. KayKit 角色内置隐藏 `Knife` 与项目长刀同名，测试拿错对象。构建预制体时直接删除不用的内置装备节点。
3. 新骨骼的贴墙姿态方向不同。保存武器局部基准姿态，每帧恢复后再沿玩家前向后收，避免累计偏移。
4. 入口拱门原始尺寸过大，第三人称相机被遮挡。运行截图发现后移除该装饰，不修改入口碰撞结构。

## 面试讲法

> 我把角色和环境表现层从玩法逻辑中拆开迭代。换模时没有改 CharacterController、对象池、AI 或 Boss 数值，而是通过编辑器构建器把第三方动画映射到项目已有的 Idle、Run、Attack、Death 接口，并把装备挂到新骨骼。场景装饰只作为按 seed 生成的无碰撞视觉对象加入，所以画面提升不会破坏程序化迷宫和 A*。这轮回归还发现了同名隐藏节点、MonoBehaviour 初始化时机和新骨骼收枪方向问题，均通过 PlayMode 与独立 Player 截图闭环。
