# v1.5.0 深渊营救与最终 Boss 开发记录

日期：2026-11-12

## 需求

旧版十关只有“找到出口”的机械目标，第十关与前九关缺少叙事和结局差异。本轮把主线改为进入地下城营救公主，并要求第十关拥有独立 Boss 战、营救结算和可重玩入口。

## 调研边界

- Unity Open Project 1：`https://github.com/UnityTechnologies/open-project-1`，Apache-2.0。采用“宏观状态拆分、事件边界清晰”的思路，没有复制样例代码。
- Unity Boss Room：`https://github.com/Unity-Technologies/com.unity.multiplayer.samples.coop`，Unity Companion License。采用“动作数据与动作执行分离”的思路，没有引入网络、Netcode 或样例技能代码。
- 放弃直接把普通精英怪放大当 Boss，因为它无法表达阶段切换、清晰预警、恢复窗口和营救结局。

## 实现决策

Boss 使用宏观 FSM：`Intro -> PhaseOne -> PhaseTwo -> PhaseThree -> Defeated`。阶段内部使用 Utility 分数选择 Cleave、Charge、CorruptionShot、Summon 和 Shockwave，并用冷却和上一次动作惩罚避免连续重复。

第十关仍保留固定种子的程序化迷宫，出口东侧追加固定矩形监牢大厅。大厅四根柱子提供掩体，中央封印承担视觉焦点，第三阶段只点亮三处安全灯。入口触发器放在闸门内侧，防止关门时把玩家锁在 Boss 房外。

普通怪使用迷宫 A*，但 Boss 房位于迷宫网格外。如果继续把房间坐标传给 `WorldToCell`，坐标会被夹到终点格，召唤怪会错误返回迷宫。因此召唤怪记录 `arenaSummon`，在 Boss 房内直接追击玩家并继续复用原伤害、动画、分离和对象池。

## 结算规则

第十关出口只进入 BossIntro，不写存档。Boss 死亡进入 Rescue、停止污染、清理召唤怪并打开牢笼；玩家进入公主触发范围后才调用 `CampaignProgress.Complete(10)`。这样可以分别测试 Boss 击杀和任务完成，也避免死亡动画开始的一瞬间直接弹出结算页。

## 测试状态

新增 10 项 EditMode 和 4 项 PlayMode 测试用例。三套程序集静态编译均为 0 errors，代码格式检查通过。激活 Unity Personal 后，EditMode 连续三轮 `32/32 PASS`，PlayMode 连续三轮 `58/58 PASS`；Windows 与 Android Release 均为 `0 errors / 0 warnings`。自动验证覆盖规则和流程边界，但尚未把最终 Boss 全流程真人试玩或本次 Android APK 真机回归写成通过。
